# sdks/c/ — Developer Guide for Claude

This file is an **additive delta** to the root `CLAUDE.md`. It covers pitfalls that only matter when *modifying* the C SDK or its FFI surface (see `README.md` for usage, API reference, and memory rules from the consumer side). Read root rules first.

## 1. The C ABI is a permanent contract — and Go consumes the same header

Every `pub unsafe extern "C" fn boxlite_*` symbol exported through `include/boxlite.h` is a stability commitment.

- Never change a signature in place. Deprecate the old one and add `boxlite_thing_v2` if a new shape is needed.
- The header is auto-generated by `cbindgen` (`build.rs:21`) from `cbindgen.toml`. Edits to `include/boxlite.h` are overwritten on every build — change the Rust source instead.
- `sdks/go/boxlite.h` is a synced copy of this header. **Breaking the C ABI breaks Go too** — re-sync the copy and re-run Go tests after any header-affecting change.

## 2. Two API layers — pick one deliberately

- **Simple API** (`boxlite_simple_*` prefix; internal type `CBoxliteSimple` = `BoxRunner` in `src/lib.rs:45`, see `tests/test_simple_api.c`). Auto-manages the runtime, buffered results, automatic cleanup. For simple callers.
- **Native API** (`CBoxliteRuntime` + `CBoxHandle`, `src/lib.rs:41-42`). Caller owns the runtime explicitly. Required for streaming output, multiple boxes, advanced configuration.

When adding a feature, decide which layer it belongs to *first*. Only mirror to the other layer if symmetry is actually needed — duplicate APIs are a maintenance tax.

## 3. Memory ownership — use `OwnedFfiPtr<T>` for nested allocations

- Every C string returned to a caller must have a `boxlite_free_*` function. Same for owned structs (`CImagePullResult`, `CBoxInfoList`, etc.).
- Use the codebase's `OwnedFfiPtr<T>` pattern. Its `Drop` impl must traverse *nested* allocations: a struct with `*mut c_char` fields has to free each inner pointer, not just the outer `Box`.
- Opaque handles (`CBoxHandle`, `CBoxliteError`, `ExecutionHandle`) are pointer-only. Never expose struct layout to C.
- Callbacks are typed `Option<extern "C" fn(...)>` so C can pass NULL. `tests/test_null_callback.c` exists because we missed this and crashed.

## 4. Test nested-allocation drops with `FREE_STR_CALLS` / `FREE_STR_LOCK`

When you add a new owned FFI payload type with nested `*mut c_char` fields, write a Rust test in `src/tests.rs` that verifies every inner allocation actually gets freed. Outer `Box` freeing without inner-string freeing is a silent leak that integration tests will not catch.

Pattern (`src/lib.rs:30,38`):

1. Acquire `FREE_STR_LOCK` (the counter is process-global; parallel tests interleave otherwise).
2. Snapshot `FREE_STR_CALLS`.
3. Allocate the payload, then drop it.
4. Assert the counter increased by the number of inner strings the type owns.

If you skip this, the leak ships and won't surface until a customer's long-running process OOMs.

## 5. Thread-safety asymmetry — document it on every new handle

- `CBoxliteRuntime` is `Send + Sync`. Safe to share across threads.
- `CBoxHandle` wraps `Arc` internally (so it can be cloned into Tokio tasks) but is **not** intended for concurrent mutation from C. Callers must serialize access per-box.
- State this expectation in the doc comment of every new handle-returning function. Implicit thread-safety claims are how C programs get racy.

## 6. Streaming respects backpressure — don't bypass `event_queue`

Streaming output (exec stdout/stderr, log events) flows through `src/event_queue.rs` with `QUEUE_CAPACITY = 4096` (see `include/boxlite.h`). When the buffer fills, producer tasks **yield** rather than drop events.

Do not introduce paths that bypass the queue, drop events on full, or assume infinite buffering. If a new event type needs different backpressure semantics, change the queue contract explicitly and document why.

## 7. Tests run in two places — both must pass

- Rust-side FFI tests: `src/tests.rs` (uses `FREE_STR_CALLS` / `FREE_STR_LOCK`). Run with `cargo test -p boxlite-c`.
- C-side compile-and-link tests: `tests/*.c`, driven by `tests/CMakeLists.txt`. Run via the project's C-test make target.
- Rust-side catches Drop/leak issues; C-side catches header-generation and ABI-compat issues. They are not redundant. Run both after every ABI change.

## 8. CMake / RPATH handling — don't use cargo for C-side tests

- macOS: `build.rs:8` sets `@rpath/libboxlite.dylib` as the install_name. C-side tests call `install_name_tool` from CMake to resolve it.
- Linux: tests rely on `LD_LIBRARY_PATH` set by the CMake harness.
- Don't add cargo-driven runs for the C-side `.c` tests — they need the CMake link environment.
